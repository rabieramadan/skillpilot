# SkillPilot - AI-Powered Training Platform

## Overview

SkillPilot is an AI-powered Learning Management System (LMS) built with Flask and PostgreSQL. It provides dynamic training courses, exams, surveys, and certificates with multi-language support. The platform supports multiple user roles and integrates with various AI providers for content generation, question creation, and advanced features like AI avatar video generation. Its goal is to deliver an engaging, efficient, and personalized learning experience through intelligent automation and dynamic content.

## User Preferences

Preferred communication style: Simple, everyday language.

## System Architecture

### Backend
- **Framework**: Flask (Python) with Blueprint-based modular routing.
- **Database ORM**: Flask-SQLAlchemy with PostgreSQL.
- **Authentication**: Session-based, role-based access control.
- **Role-Based Access Control**: Supports Superadmin, Admin, Teacher, and Student roles with differentiated permissions.

### Frontend
- **Templating**: Jinja2.
- **Styling**: Custom CSS for responsive design, Font Awesome.
- **UI/UX**: Features a three-column chat layout with chat history and file attachments. UI components follow a design system with light/dark and RTL support. Accessibility adheres to WCAG 2.2 AA guidelines.

### Database Design
- **Core Models**: User, Course, Exam, Survey, Enrollment, SiteSettings.
- **Certificate Specification**: Tracks eligibility and issuance for course completion.
- **Personalization**: Models for LearnerProfile, Skill, LearningPath, and EthicsCompetency.
- **Authoring**: Models for AuthoringDraft, ContentVersion, ScormPackage, XApiStatement.
- **Engagement**: Models for Badge, XPEvent, ForumThread, PeerReview, Cohort, GuardianLink, LiveSession.
- **Analytics**: Models for CohortAnalyticsSnapshot, SentimentSignal, AtRiskAlert.
- **SkillMatch**: Models for Occupation, OccupationSkill, LabourMarketSignal, TeacherPDTrack.
- **Enterprise**: Models for Organization, SsoConfiguration, ApiKey, AuditEvent, ConsentRecord, DataRequest.
- **Notifications**: Notification model for in-app alerts.
- **Key-Value Settings**: `KeyValueSetting` model for flexible storage of system configurations like SMTP settings and AI API credentials.

### Technical Implementations
- **AI Integration**: Dynamic selection and utilization of various AI providers for content, questions, and AI avatar video generation. API keys are securely managed. Includes a `programming_tutor` tool for structured coding lessons and a `PROMPT_LIBRARY` for one-click prompt selection.
- **Document Processing**: Integration for PDF, Word, and PowerPoint generation/processing, including dynamic PDF certificate generation.
- **Multi-language Support**: Extensive support for English and Arabic.
- **Security**: CORS, Werkzeug ProxyFix, and robust SAML 2.0 SSO verification using `signxml` for XML signature validation.
- **System Administration**: Centralized `/admin/system` page for managing system health, audit logs, roles, API keys, email settings, scheduled jobs, and backups.
- **Developer Portal**: Provides access to API keys, OpenAPI spec, and usage examples.
- **EthicalSense Hub**: Dedicated module for ethical competency learning, including payment processing and admin settings for module management.
- **EthicalSense — five global AI ethics principles**: every assessment is now anchored to the international convergence framework — `transparency`, `fairness`, `non_maleficence`, `responsibility`, `privacy` — defined as `AI_ETHICS_PRINCIPLES` in `app/routes/ethics.py` (bilingual EN/AR name + description + Font Awesome icon). New endpoint `GET /api/ethics/principles` returns the framework. `POST /api/ethics/generate-scenario` rotates through the five principles per question, injects the principle id/name/definition into the AI prompt, requires the model to return `principle`, `principle_name`, and `rationale`, and persists those on each scenario record (also surfaced back to the client in the response). The hub (`templates/ethicalsense_hub.html`) renders a "Five global AI ethics principles" grid above the level cards.
- **Notifications Center**: In-app notification system with bell icon UI, polling for unread counts, and optional email digests. The notification service (`app/services/notification_service.py`) now also exposes `send_email(to_email, subject, text, html)` for one-off transactional sends and `notify_course_audience(course_id, kind, title, body, …)` which fans an in-app notification out to enrolled students (status approved/active/completed), assigned `CourseInstructor`s, and (optionally) all admins/super_admins. Both helpers are fail-soft — they never raise, only log. Course publish/unpublish (super_admin.py `update_course`) and exam creation (`POST /api/courses/<id>/exams`) now call this helper automatically.
- **Class Broadcast (admin → students)**: `POST /admin/api/courses/<course_id>/notify-students` accepts `{user_ids:[], title, body, severity, send_email}`, validates that each id is currently enrolled (approved/active/completed) in the class, creates an in-app notification per student, and optionally sends an immediate one-off email per recipient. The Admin Dashboard course list (`templates/admin_dashboard.html`) has a blue bullhorn button per row — `showClassBroadcast(courseId, courseTitle)` — that opens a modal with checkbox-per-student (default all checked, with Select-all/Clear), title + severity + message + "Also send email" toggle, and then POSTs to that endpoint.
- **Self-service password reset by email**: `POST /api/auth/forgot-password/email-link` accepts `{username|email}` and (when an account with an email exists) generates a `PasswordResetToken` and emails a one-click link to `/reset-password?token=<raw>`. To prevent account enumeration it always returns the same generic success message. The legacy admin endpoint `POST /api/auth/forgot-password/admin-reset` now also auto-emails the link if the account has an email and SMTP is configured (`KeyValueSetting('smtp_config')`); the raw token is only returned in the JSON response when email delivery failed, so admins can still hand it over manually. New page `GET /reset-password` (template `templates/reset_password.html`) reads the token from the URL, asks for + confirms a new password, then POSTs to `/api/auth/reset-password`. Landing page (`templates/landing.html`) now has a teal "Email me a reset link" button alongside the existing security-questions flow.
- **Smart Assessment**: Assessment attempts with spaced retention scheduler, rubric grader, and explainable flag rules for transparent proctoring.
- **API Keys & Integrations Page**: `/admin/integrations` provides a centralized interface for managing and testing external API credentials for various AI providers and payment gateways.
- **HTTP Security Headers**: An `@app.after_request` hook in `app/__init__.py` sets `Content-Security-Policy`, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, and (in prod) `Strict-Transport-Security` on every response. CSP is currently permissive (`'unsafe-inline'` allowed) due to legacy inline scripts in Jinja templates; tightening to a nonce-based CSP is tracked as future work.
- **XSS-safety frontend helper**: `static/js/skp-safe.js` exposes `SKP.escape(v)`, `SKP.t\`…${untrusted}…\``, and `SKP.setHTML(el, html)` and is loaded globally from `templates/_skp_base.html`. New JS code must use these instead of raw `innerHTML +=`.
- **XML hardening**: SAML SSO (`app/services/sso_service.py`) and SCORM manifest parsing (`app/services/scorm_service.py`) use `defusedxml.ElementTree` to mitigate XXE / billion-laughs attacks.
- **CSV formula-injection guard**: All 4 CSV export endpoints in `app/routes/insights.py` route their data rows through `_csv_safe` / `_csv_row`, which prefixes any cell beginning with `=`, `+`, `-`, `@`, `\t`, or `\r` with a single quote.
- **xAPI transport**: `app/services/xapi_service.py` refuses to send Basic-Auth credentials over non-HTTPS LRS endpoints (fail-closed).
- **Per-class Attendance & Exams from the Course list (Admin Dashboard)**: each row in the `loadCourses()` table now has a teal Attendance button (`showClassAttendance`) and a violet Exams button (`showClassExams`) — both scoped to that specific course/class id. The generic top-bar "Attendance" button in `templates/index.html` is now permanently hidden in `static/js/auth.js` (attendance is class-scoped only). The class Attendance modal lets admins/teachers pick a session date, auto-loads the enrolled-trainee roster via `GET /api/attendance/class/<course_id>/date/<YYYY-MM-DD>`, mark each as present/absent/late/excused with a note, and POST back as `{records:[{student_id, status, notes}]}`. The class Exams modal lists current exams (count of submissions, threshold, status) and offers a one-line "Create new exam" form posting to `POST /admin/api/courses/<course_id>/exams`. **Both surfaces feed straight into the Batch Monthly Report**: every saved attendance row is counted into working_days / absent_days / Attendance %, and every exam created becomes a new column in the Excel report (with each trainee's best score pre-filled).
- **Batch Monthly Report (Excel) — editable preview workflow**: Admin Dashboard → Certificates card → "Batch Monthly Report" opens a modal that fetches `GET /admin/api/courses/<id>/batch-report-data?month=YYYY-MM` (in `app/routes/super_admin.py`). The JSON payload merges live data from every relevant source — enrolled trainees (User via Enrollment), distinct attendance dates + `Attendance.status='absent'` counts, open/acknowledged `AtRiskAlert` counts as the warning-letter seed, all `Exam` definitions with the best `ExamResult.score` per trainee, and the computed `final_grade` (override > `Enrollment.final_grade` > avg of exams) — together with any previously-saved edits from the new `enrollment_monthly_rubrics` table. The modal renders a sticky-header HTML table where each cell (warnings, the 10 performance criteria 1–4, every exam score, the overall grade, notes) is editable. "Save & Export to Excel" POSTs the edits to `POST /admin/api/courses/<id>/batch-report.xlsx?month=YYYY-MM`, which upserts an `EnrollmentMonthlyRubric` row per (enrollment, month) and then generates the same brand-matching workbook (3 logos + teal/gold) via `generate_batch_report_xlsx(..., overrides=...)`. The original `GET .xlsx` endpoint still works for a quick zero-edit download. New table `enrollment_monthly_rubrics` (one row per enrollment + month) holds `performance_scores` (JSON), `warning_letters`, `final_grade_override`, `notes`.
- **Secrets policy**: `config.yaml` is for non-secret defaults only — every API key resolves from env vars / Replit Secrets first, then the `KeyValueSetting` admin UI. `exports/`, `users.json`, `skillpilot_deployment/`, and `*.bak` are git-ignored.
- **Role-based top menu groups**: `static/css/advanced.css` now hides the entire `.menu-group.instructor-or-admin-only` and `.menu-group.instructor-only` sections by default (mirroring the existing `admin-only` rule); `static/js/app.js`'s `updateRoleUI()` toggles `.role-visible` on whatever element carries the role class — section or item. The `Teaching` section in `templates/index.html` is now tagged `instructor-or-admin-only`, so students see no Teaching dropdown header. The legacy `Artificial Intelligence Laboratory` entry under the Learning menu has been removed from both `templates/index.html` and `templates/_top_menu.html` (Agentic AI Lab is still reachable from inside an enrolled class).
- **Prompt Library / Templates page seed**: `prompts_library.json` ships a curated starter set of 17 prompts spread across the existing 5 categories (General, Analysis, Coding, Creative, Teaching), surfaced at `Templates` menu → `/app?tab=library` via `GET /api/prompts/library`. Each prompt has a placeholder block (`[PASTE … HERE]`) so users can drop in their own context. Admin can still add/edit/delete via the existing POST/PUT/DELETE endpoints in `app/routes/prompts.py`.
- **PWA (installable on mobile)**: SkillPilot is installable as a Progressive Web App. The web manifest lives at `static/manifest.json` (name=SkillPilot, theme `#1a5c5e`, `start_url=/app`, `scope=/`, icons at 192/512/1024). The service worker at `static/sw.js` is **deliberately privacy-conservative**: HTML navigations and `/api/*` requests are **network-only** (never cached, so authenticated/admin pages can never be served offline after logout on shared devices and role-based UIs always reflect the current session); only truly public `/static/*` assets and font/css/js/image extensions are cached cache-first under the `skp-static-skp-v2` cache. The SW also explicitly never intercepts `/admin/login`, `/api/auth/*`, or `/reset-password`. Both files are re-served from root via `app/__init__.py` routes `GET /sw.js` (sets `Service-Worker-Allowed: /` so the SW can control the whole site even though the file lives in `/static/`) and `GET /manifest.json`. PWA + Apple meta tags are centralised in `templates/_pwa_meta.html` and included from `_skp_base.html`, `landing.html`, `index.html`, and `admin_dashboard.html`. Comprehensive responsive CSS already lives in `static/css/mobile.css` (loaded by all four entry templates). Bump `CACHE_VERSION` in `static/sw.js` whenever the precache list changes.
